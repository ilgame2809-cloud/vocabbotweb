# VocabBotWeb — фронтенд (React + Vite + TS)

## ⚠️ Временный режим: без регистрации

Пока сайт тестируется и у него нет реальных пользователей, экраны входа/
регистрации убраны из UI. При первом заходе фронт сам логинится под одним
общим демо-аккаунтом (`demo@vocabbot.local`), создавая его на backend при
первом запуске — значит **у всех, кто сейчас открывает сайт, общий
аккаунт и общий прогресс изучения**. Это осознанное временное решение для
удобства тестирования, а не баг.

Когда дойдёт до реального запуска с разными людьми — нужно откатить: файлы
`src/pages/Login.tsx` и `src/pages/Register.tsx` не удалены, просто не
подключены в `src/App.tsx`. Вернуть роуты `/login` и `/register`, убрать
автовход в `src/context/AuthContext.tsx` (см. комментарий там же).

## Важное упрощение относительно дизайна

В `card-design.html` было два режима ответа: "Повторение" (4 кнопки
Again/Hard/Good/Easy) и "Новое слово" (3 кнопки Знаю/Почти/Не знаю).
Backend же принимает только 4 значения `ReviewQuality` независимо от того,
новое слово или нет — сам разбирается по внутренней фазе SM-2. Поэтому во
фронте один и тот же набор из 4 кнопок показывается всегда — это осознанное
упрощение под реальный контракт API, а не эстетическое решение.

## Как запустить локально

```bash
cd vocabbot-frontend
npm install
cp .env.example .env
# в .env пропиши VITE_API_URL — адрес твоего backend (локальный или Render)
npm run dev
```

Откроется на `http://localhost:5173`.

⚠️ Если backend крутится локально на `https://localhost:5001` — там обычно
самоподписанный dev-сертификат, браузер может ругаться на него при первом
запросе. Проще для локальной разработки временно указать в `.env` адрес
твоего API на Render (`https://имя-сервиса.onrender.com`) — у него уже
нормальный сертификат.

## Деплой на Vercel/Netlify

1. Запушь эту папку в тот же (или отдельный) git-репозиторий.
2. На Vercel/Netlify — Import Project → укажи корень `vocabbot-frontend`
   (если фронт и бэкенд в одном репозитории, важно указать правильную
   Root Directory при импорте).
3. Build command: `npm run build`, Output directory: `dist` (Vercel обычно
   определяет это сам для Vite-проектов).
4. Environment Variables → добавь `VITE_API_URL` = адрес backend на Render.
5. После деплоя — вернись на Render и обнови `FrontendOrigins__0` (в
   Environment Variables backend-сервиса) на реальный адрес фронта
   (`https://твой-сайт.vercel.app`), иначе CORS заблокирует запросы.
